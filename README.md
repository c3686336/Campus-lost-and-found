# Campus Found · KAIST 분실물 센터

분실 신고 → 습득물 접수 → 매칭 → 반환 신청 → 관리자 소유권 확인 → 인도를 지원하는 시연용 PWA입니다. Linux와 Node.js 24 이상을 실행 기준으로 하며 외부 패키지, 유료 서비스, 앱스토어 계정 없이 실행합니다.

## 실행

Linux 터미널에서 프로젝트 폴더로 이동한 뒤 실행합니다. Node.js 24 이상이 PATH에 있어야 합니다.

```sh
node --version
sh ./start.sh
```

브라우저에서 http://localhost:3000 에 접속합니다. 서버를 종료하려면 실행한 터미널에서 Ctrl+C를 누릅니다. `start.sh`는 작업 디렉터리를 맞추고 Node 버전을 확인한 뒤 `node server.mjs`를 실행합니다. 패키지 설치 단계는 필요하지 않습니다.

포트와 데이터 경로는 환경변수로 지정할 수 있습니다.

```sh
PORT=3001 DATA_DIR="$PWD/.data" sh ./start.sh
```

기본 접속 주소는 같은 컴퓨터에서만 접근할 수 있는 `127.0.0.1`입니다. 다른 컴퓨터에서 Linux 시연 서버에 접속해야 할 때는 접근 범위와 HTTPS를 구성한 뒤 `HOST`를 지정합니다.

HTTPS를 종료하는 프록시 뒤에서 시연할 때는 `PUBLIC_ORIGIN=https://demo.example`처럼 실제 브라우저 접속 출처를 명시합니다. 프록시는 공개 `Host` 헤더를 유지해야 하며, 백엔드는 비공개 인터페이스에 둡니다. 이 설정이 출처 검사와 Secure 세션 쿠키에 함께 적용됩니다. 클라이언트가 보낸 `X-Forwarded-*` 헤더만으로 HTTPS를 신뢰하지 않습니다. `PUBLIC_ORIGIN`은 HTTPS 인증서를 발급하거나 프록시를 실행하는 기능이 아닙니다.

| --- | --- | --- |

| 습득자 | finder@kaist.ac.kr | CampusDemo!24 |

이 계정과 예제 물품은 새 데이터베이스를 처음 실행할 때 생성됩니다. 저장 내용은 서버를 재시작해도 유지됩니다. 시연 계정은 공개된 테스트 계정이므로 실제 개인정보나 실제 신분증을 넣지 마세요.

KAIST 이메일 가입은 데모 확인 코드로 이메일 확인 절차를 시연합니다. KAIST 이메일이 없는 교내 구성원은 증빙 문서(PDF 또는 이미지)를 제출하고 관리자 승인을 받은 뒤 로그인합니다. 실제 메일 발송·학교 시스템 연동은 `lib/identity-provider.mjs`의 제공자 구현으로 교체할 수 있습니다. 이는 신원 확인의 인터페이스를 구현한 시연이며, 실제 외부 인증 기관과 연결되지는 않습니다.

## 합의된 범위

- 스토어 출시를 제외하고 설치 가능한 PWA로 구현합니다.
- 호스팅은 로컬 시연 서버를 제공합니다.
- 로그인 신원 확인은 인터페이스와 데모 제공자로 구현합니다.
- 권한은 `User` / `Administrator` 두 단계입니다.
- 학기 중 가용성 95%는 제외하고 기능 및 간단한 부하 테스트로 검증합니다.
- 습득자는 습득 신고만 합니다. 장소 변경, 정보 정정, 검사, 반환 승인 및 인도 확인은 관리자 권한입니다.

문서에서 미정이던 습득물 보관 기간은 30일, Open 분실 신고 보관 기간은 90일, 완료 데이터 보존 기간은 180일로 초기 설정했습니다. 관리자 화면에서 바꿀 수 있습니다. 자동 매칭은 같은 분류이며 발견 날짜가 분실 날짜 이상인 후보를 생성하고, 동일 장소 우선·최신 발견 순으로 표시합니다. 위험 물품은 표시를 통해 별도 처리하고 승인된 신청자에게만 지정 반환 장소를 공개합니다.

PWA는 정적 화면 파일만 오프라인에 보관합니다. 로그인, 신고, 조회·수정에는 서버 연결이 필요하며, 개인정보나 API 응답은 서비스 워커에 저장하지 않습니다. localhost는 브라우저의 보안 컨텍스트로 PWA 설치를 지원합니다. 다른 기기에서 접속하는 임시 시연 환경은 HTTPS가 필요하며, 실제 HTTPS 호스팅과 휴대폰 설치 검증은 별도 환경에서 수행해야 합니다.

## 시연 순서

1. 분실자 계정으로 로그인해 분실 신고를 등록합니다.
2. 로그아웃 후 습득자 계정으로 같은 분류의 습득물을 등록합니다. 접수 장소 안내를 확인합니다.
3. 관리자로 로그인해 물품을 검사하고 보관 장소·비공개 특징을 기록합니다.
4. 분실자로 로그인해 매칭 알림을 확인하고, 비공개 특징을 설명해 반환을 신청합니다.
5. 관리자로 로그인해 추가 증빙을 요청하거나 승인합니다. 승인된 사용자는 **수령 장소 확인** 버튼으로 장소를 열람하며, 열람자·시각은 관리자 감사 기록에 남습니다. 일반 목록 응답에는 수령 장소를 포함하지 않습니다.
6. 관리자가 인도를 기록하면 물품과 연결된 분실 신고가 검색에서 사라집니다.

관리자 화면에서는 다중 반환 신청 비교, 후보 수동 관리, 위험 물품 표시·기관 이관, 미수령 폐기·기부, 오인도 사고 차단·해제, 외부 구성원 승인·접근 차단, 감사 기록, 보관 정책도 시연할 수 있습니다.

## 검증

```sh
node --test tests/*.test.mjs
node scripts/load-test.mjs
```

테스트는 임시 데이터베이스를 사용해 시연 데이터를 건드리지 않습니다. 핵심 정상 흐름뿐 아니라 권한 위반, 개인정보 비노출, 상태 전이 거부, 중복 신고, 경쟁 신청, 업로드 검증과 잘못된 입력을 확인합니다. 부하 테스트는 로컬 서버에서 동시 요청의 성공률과 응답 시간을 출력합니다. 측정 결과는 해당 컴퓨터에서의 시연 결과이며 학기 전체 운영 가용성을 의미하지 않습니다.

부하 스크립트는 조회 평균 3초·등록 평균 5초 기준도 검사하며 실패한 요청이나 기준 초과가 있으면 실패 종료합니다. UI/PWA 단위 회귀 검증은 `npm test`에 포함됩니다. 실제 브라우저 검증은 개발용 Playwright가 있는 환경에서 선택 실행합니다. 애플리케이션 실행과 기본 테스트에는 외부 패키지가 필요하지 않습니다.

```sh
# Playwright가 설치된 개발 환경에서
npm run test:browser
# 외부 테스트 도구를 사용할 경우 모듈/브라우저 경로 지정 가능
# PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs BROWSER_EXECUTABLE=/path/to/chrome npm run test:browser
```

브라우저 검증은 격리된 데이터와 프로필을 사용합니다. 가입·문서 심사·사진 신고·반환 승인·장소 열람·인도·입력 유지·모바일 너비·오프라인 화면을 검사하고 `test-results/browser`에 스크린샷과 결과를 저장합니다.

2026-11-06 수정본은 macOS, Node.js v24.22.1에서 자동 회귀 테스트 **35개**, 동시 요청 10개로 총 **200건**을 모두 통과했습니다. 조회 평균 6.06ms, 등록 평균 6.72ms로 시연 임계값을 통과했습니다. 실제 Chrome에서도 문서 승인·사진 신고·반환·열람 감사·모바일 너비·오프라인 화면을 검증했습니다. 범위와 한계는 `docs/COMPLIANCE.md`에 기록했습니다.

수정 전 기록: 2026-11-05 Ubuntu(WSL), Linux용 Node.js v24.22.2에서 기능 테스트 11개와 동시 요청 200건이 모두 통과했습니다. `start.sh`를 다른 작업 디렉터리에서 실행해 HTTP 응답과 SIGTERM 정상 종료도 확인했습니다.

## 구조

- `server.mjs`: HTTP API, 세션·권한 검사, 정적 파일 제공
- `start.sh`: Linux/POSIX 셸 실행 진입점
- `lib/`: 업무 규칙, SQLite 저장 및 신원 확인 제공자
- `public/`: 한국어 반응형 화면, manifest, 서비스 워커
- `tests/`: 기능·보안 경계 검증
- `scripts/load-test.mjs`: 시연용 동시 요청 검사
- `scripts/browser-test.mjs`: 선택 실행하는 실제 브라우저 시나리오 검사
- `docs/REQUIREMENTS.md`: 요구사항 추적 및 적용한 변경사항
- `docs/COMPLIANCE.md`: 원본 SRS 23페이지와 고객 답변 7항목의 대조·검증 범위
- `API.md`: 프런트엔드·서버 API 계약

비밀번호는 해시로 저장하며 저장 페이로드와 증빙 문서는 암호화합니다. `.data`에는 로컬 데이터베이스와 암호화 키가 함께 있으므로 폴더 전체를 읽을 수 있는 운영체제 사용자는 데이터를 복구할 수 있습니다. `.data`와 백업은 공개 저장소에 포함하지 않습니다. 서버는 기본적으로 로컬 인터페이스에만 바인딩합니다. 외부 시연을 위해 서비스를 공개한다면 HTTPS, 비밀 관리, 실제 인증 제공자, 접근 대상을 해당 환경에 맞게 구성해야 합니다.

## 백업과 복구

서버 시작 및 요청 처리 시 날짜를 확인해 하루 한 번 암호화된 SQLite 스냅샷을 `.data/backups`에 저장하고 최근 7개를 유지합니다. 관리자는 `POST /api/backup`으로 현재 데이터의 별도 스냅샷을 생성할 수도 있습니다. 서버가 중지된 동안에는 백업 작업도 실행되지 않습니다.

각 계정·물품·신청·감사 기록은 별도 암호화 레코드로 저장하고, 변경된 레코드만 하나의 SQLite 트랜잭션으로 반영합니다. 이전 버전의 단일 암호화 JSON DB는 시작 시 자동 변환하며 원래 키를 계속 사용합니다. 조회는 매번 전체 DB를 저장하지 않고 최대 1분 주기로 만료 정리를 실행합니다. 변경 요청에서는 만료 정리를 즉시 적용합니다. 매칭은 분류별 메모리 인덱스로 불필요한 비교를 줄이지만, 단일 서버·전체 응답 구조이므로 대규모 운영 용량을 보장하지 않습니다.

업무 저장이 끝난 뒤 자동 백업만 실패하면 업무 처리는 성공으로 유지하고 관리자 운영 설정에 백업 오류를 표시합니다. 다음 유지관리 시 재시도하거나 **현재 데이터 백업** 버튼으로 즉시 재시도할 수 있습니다. 수동 백업 실패는 503 오류로 반환합니다. DB 쓰기 자체가 실패하면 메모리와 DB 변경을 함께 롤백합니다.

복구할 때는 서버를 종료하고 현재 `.data` 폴더를 따로 보관한 다음, 선택한 스냅샷을 `.data/campus.sqlite`로 복사합니다. 원본 데이터와 함께 생성된 `.data/encryption.key`가 반드시 필요합니다. 키가 다른 스냅샷은 복구할 수 없습니다. 복구 후 서버를 다시 시작하면 기존 세션은 만료되어 다시 로그인해야 합니다.

완료·철회된 신고 및 연결된 반환 증빙, 알림·감사 기록·문의, 심사가 끝난 가입 문서는 설정된 보존 기간에 따라 다음 요청 처리 시 정리됩니다. 정상 이용 중인 계정은 유지됩니다. 오래된 백업은 스냅샷 순환에 따라 제거되므로 백업에도 삭제 이전 데이터가 일시적으로 남을 수 있습니다.
