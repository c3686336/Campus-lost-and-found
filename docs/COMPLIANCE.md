# SRS 및 고객 합의 조건 대조

기준일: 2026-11-06. 원본 `Team10_SRS.pdf` v1.0(2026-10-07), 전체 23페이지를 읽고 대조했다. 원본의 절 번호와 PDF 페이지 번호는 2페이지 차이가 있으므로 아래에는 절 번호를 사용한다. 고객이 확인한 7개 답변을 원본보다 우선한다.

이 문서는 구현 증거와 검증 한계를 함께 기록한다. `충족`은 합의된 로컬 시연 범위에 해당하는 코드가 있다는 뜻이다. 실제 브라우저·휴대폰·HTTPS 환경 결과와 최종 자동 테스트 결과는 검증 기록에 별도로 남긴다. 원문에 남은 모순이나 미정 값은 임의로 완전 충족으로 처리하지 않는다.

## 고객 합의 7항목

| 답변 | 적용 기준 | 구현 근거 | 판정 |
| --- | --- | --- | --- |
| 1. 스토어 제외, PWA 허용 | 네이티브/WebView 배포와 개발자 계정 불필요 | `public/manifest.webmanifest`, `public/sw.js`, 설치 안내 | 충족. 실제 휴대폰 설치는 환경 검증 |
| 2. 시연 때만 간이 호스팅 | 단일 로컬 서버로 실행, 상시 운영 의무 없음 | `start.sh`, `server.mjs`, `HOST`/`PORT`/`DATA_DIR`/`PUBLIC_ORIGIN` | 충족. 다른 기기 접속은 HTTPS 설정 필요 |
| 3. 로그인 신원 확인 추상화 허용 | 실제 학교 인증·메일 발송 대신 인터페이스와 데모 제공자 | `IdentityVerifier`, `DemoIdentityProvider`, 제공자 주입 | 충족. 물품 소유권 승인은 여전히 관리자 결정 |
| 4. 권한 2단계 | User/Administrator만 허용 | `publicUser`, `admin`, `userAction`, 역할별 UI | 충족. finder는 별도 권한 계층이 아닌 일반 사용자의 행위 |
| 5. 95% 관련 제외 | 학기 운영 SLA 제외, 기능 및 제한된 시연 부하 검증 | `tests/`, `scripts/load-test.mjs` | 충족 범위의 검증. 실사용자 1%·학기 가용성 증거는 아님 |
| 6. KAIST 이메일 없는 외부 사용자 문서 인증 가입 | 문서 제출 후 관리자 승인 전 로그인 거부 | `register`, `userAction`, `login`, 일반 사용자에게 문서 비공개 | 충족. 문서의 적합성은 데모 관리자 심사 |
| 7. finder는 습득 신고만 | 신고 뒤 정정·보관 장소 변경·검사·인도는 관리자 | `editItem`, `itemAction`, 습득 신고 화면, 권한 테스트 | 충족. 본인의 Open 분실 신고 수정·철회는 별개로 허용 |

원본 2.2.1과 2.7은 비 KAIST 이메일 사용자의 재학·재직 등 학교 소속 증빙을 예시로 명시한다. 고객 답변 6은 문서를 통한 외부 사용자 가입 경로를 확인한다. 프로그램은 이메일 도메인만으로 외부 사용자를 거부하지 않고, 문서 진위·가입 적합성은 관리자가 심사한다. 실제 외부 인증기관 검증을 수행했다고 표현해서는 안 된다.

분실 신고 하나가 여러 물품의 소유권 승인에 중복 사용되는 것은 차단한다. 승인된 반환 신청에 연결된 Open 분실 신고도 원문 REQ-2.6대로 수정·철회할 수 있다. 철회·기한 초과 삭제 시 반환 신청의 연결만 해제하고, 이미 기록된 소유권 승인 자체를 취소하지 않는다.

## 원문 모순과 적용 결정

- **권한 3단계 대 2단계:** 5.3.2 Intermediate Administrator를 제거하고 합의 4 적용.
- **가입:** REQ-1.1·5.3.1 KAIST 이메일 전용 문구보다 합의 6의 문서 승인 외부 사용자 허용을 우선.
- **finder 동작:** 2.2.6·2.7의 finder 정정·수령 표시는 합의 7로 대체.
- **PWA:** 2.1·2.4의 WebView/스토어 발행은 합의 1로 대체.
- **매칭 시 검색 숨김:** 3.1의 matched items 숨김 문구보다 REQ-4.2와 REQ-5.5 적용. 후보 생성만으로 숨기지 않음.
- **매칭 대상:** REQ-5.1의 `Open`×`Stored`를 그대로 적용. `Recovery requested` 중 새 자동 매칭을 생략하는 것은 누락이 아님. 대기 신청이 모두 거절되어 Stored로 복귀하면 새 후보를 생성.
- **위험 물품 반환 장소:** 5.2.1의 비관리자 전체 비공개 문장보다 구체적인 REQ-8.2 우선. 실제 보관 장소는 계속 관리자만 조회.
- **오인도 후 조작:** 4.7.2와 REQ-7.5 사이의 차이는 관리자 해결을 허용하는 REQ-7.5 적용.
- **보관일 TBD:** REQ-9.3의 TBD-4는 부록 C의 매칭 기준을 가리키는 잘못된 번호. 보관 30일·Open 신고 90일·완료 기록 180일을 설정 가능한 시연 기본값으로 적용.
- **물리 검사·문서 진위·인도:** 소프트웨어는 필수 정보와 관리자 결정을 기록하고 상태 전이를 검증한다. 현실의 실물·신분을 자동 인증한 것으로 취급하지 않음.
